# Marcel 评测台

拿同一批考题，量化「这一版提示词 / harness」配「这个模型」到底干得怎么样。

```bash
pnpm eval
```

浏览器会自动打开评测台（`http://127.0.0.1:4780`）。第一次用：

1. 打开 Docker Desktop。
2. 点右上角「设置」，填 API 地址和 Key，再点「从接口读取可用模型」，把要考的模型加进来。
3. 点「开始一轮」，选模型、选题、每题考几次（建议 3 次），开始。

改完提示词或 Rust 代码后再「开始一轮」，它会按你当前的代码重新编译（有未提交的改动也算），然后在左侧勾选两轮点「对比」，就能看到哪些题变好了、哪些变差了，以及这个差别算不算得上数。

## 每场考试发生了什么

1. 起一台全新的 Docker 靶机（Debian + sshd），执行这道题的 `setup.sh` 布置现场，然后把题目文件删掉，agent 看不到判卷脚本和参考答案。
2. 调起评测入口：它跑的是 App 里那条**真实的 agent 循环**，包括提示词、工具、风险评估、审批、上下文压缩和子 agent，经 SSH 连靶机干活。
   - 配置目录是全新的空目录，不带你本机的长期记忆、附加指令、插件和技能。
   - 审批自动批准（并记下次数），agent 提问时按题目预设的答案回答。
   - 作用在「用户本机」的工具（本机子 agent、本机与远端之间传文件等）会被拦下，免得在跑评测的这台电脑上动手。
3. 跑 `check.sh` 判卷，再检查 agent 有没有执行禁止的命令、最终回复里有没有该有的答案。
4. 销毁靶机。

API 报错、靶机起不来这类不是模型的错，记为「作废」并自动重考，不计入成绩。

所有模型请求都经评测台内置的中转站转发：真实 Key 只在它手里，并且**同一时刻最多 4 个请求在路上**（子 agent、审批模型并行发的请求也算在内）。

## 出题

每道题一个文件夹 `evals/tasks/<题目id>/`：

| 文件 | 作用 |
| --- | --- |
| `task.json` | 标题、分类、给 agent 的话（`prompt`）、超时、预设回答、禁止命令、答案里必须出现的内容、是否暗题 |
| `setup.sh` | 以 root 在新靶机里布置现场，不联网 |
| `check.sh` | 判卷：退出码 0 为通过，最后一行输出原因 |
| `solve.sh` | 参考解法，只用来验证判卷脚本本身写对了 |

新题写好后先跑一遍自测：`bash evals/docker/selftest.sh`。它会检查每道题「布置完时判为不通过、执行参考解法后判为通过」。

靶机镜像改了以后要重建：`docker build -t marcel-eval-target:latest evals/docker`。

## 文件都在哪

- 成绩和对话回放：`evals/results/`（不入库）
- 本机配置（含 API Key）、编译缓存、临时工作目录：`evals/.local/`（不入库）
